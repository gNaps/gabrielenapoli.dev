## Login con Twitch in Next.js e Auth.js

<br />
Oggi costruiamo un'app Next.js dove l'utente **entra col suo account Twitch**
e vede la lista dei canali che segue, con l'indicazione di chi è in live in
quel momento. OAuth vero, API vere, niente scorciatoie: alla fine avrai un
flusso di autenticazione completo che puoi riusare per qualsiasi provider.
<br />
I link utili prima di partire:
<br />
- [Docs API Twitch](https://dev.twitch.tv/docs/api)
- [Docs Next.js](https://nextjs.org/docs)
- [Docs Auth.js](https://authjs.dev)
<br />
### 🔧 Setup: la console Twitch
<br />
Il primo passo è sulla [console developer di
Twitch](https://dev.twitch.tv/console): crea un account se non ce l'hai, poi
registra una nuova applicazione. Il campo importante è l'**OAuth Redirect
URL**, dove va inserito:

```text
http://localhost:3000/api/auth/callback/twitch
```

È l'indirizzo a cui Twitch rispedirà l'utente dopo il login, ed è Auth.js a
gestirlo per noi. Dalla console recupera **Client ID** e **Client Secret** e
mettili in un file `.env.local`:

```bash
AUTH_TWITCH_ID=il-tuo-client-id
AUTH_TWITCH_SECRET=il-tuo-client-secret
AUTH_SECRET=una-stringa-casuale-lunga
```

Quel `AUTH_SECRET` serve ad Auth.js per firmare le sessioni: generalo con
`npx auth secret` o con qualsiasi generatore di stringhe casuali.

> Occhio ai nomi delle variabili: in Next.js tutto ciò che ha il prefisso
> `NEXT_PUBLIC_` finisce **nel bundle del browser**, leggibile da chiunque
> apra i DevTools. Client secret e chiavi di firma non devono mai averlo: le
> variabili `AUTH_*` qui sopra restano sul server, dove i segreti devono
> stare.

### 📦 Setup: il progetto
<br />
Creiamo il progetto e installiamo Auth.js (il pacchetto si chiama ancora
`next-auth`, nella versione 5):

```bash
npx create-next-app@latest twitch-follows
cd twitch-follows
npm install next-auth@beta
```

### 🔑 La configurazione di Auth.js
<br />
Tutta la configurazione vive in un file `auth.ts` nella radice del progetto:
qui dichiariamo il provider Twitch (Auth.js ne ha uno pronto), gli **scope**
che ci servono e due callback per portarci a casa il token di accesso.

```typescript
// auth.ts
import NextAuth from 'next-auth';
import Twitch from 'next-auth/providers/twitch';

export const { handlers, auth, signIn, signOut } = NextAuth({
  providers: [
    Twitch({
      authorization: {
        params: {
          // oltre al login, chiediamo di leggere i canali seguiti
          scope: 'openid user:read:email user:read:follows',
        },
      },
    }),
  ],
  callbacks: {
    jwt({ token, account }) {
      // al primo login, salviamo il token Twitch e l'id utente
      if (account) {
        token.accessToken = account.access_token;
        token.userId = account.providerAccountId;
      }
      return token;
    },
    session({ session, token }) {
      // e li esponiamo nella sessione, per usarli lato server
      session.accessToken = token.accessToken as string;
      session.userId = token.userId as string;
      return session;
    },
  },
});
```

Tre cose da notare. Primo: il provider ufficiale basta e avanza, ci
aggiungiamo solo gli `scope` extra (il predefinito gestisce il login, ma per
leggere i canali seguiti serve `user:read:follows`). Secondo: client id e
secret non compaiono nel codice, Auth.js li legge da solo dalle variabili
`AUTH_TWITCH_*`. Terzo: i callback `jwt` e `session` sono il passaggio di
mano del token: Twitch lo consegna ad Auth.js, noi lo travasiamo nella
sessione per poterlo usare nelle chiamate API.
<br />
Il route handler è di una modestia imbarazzante:

```typescript
// app/api/auth/[...nextauth]/route.ts
import { handlers } from '@/auth';

export const { GET, POST } = handlers;
```

### 🚪 La pagina di login
<br />
Niente `use client`, niente hook: una **server action** e un bottone.

```tsx
// app/login/page.tsx
import { signIn } from '@/auth';

export default function LoginPage() {
  return (
    <main className="login">
      <form
        action={async () => {
          'use server';
          await signIn('twitch', { redirectTo: '/' });
        }}
      >
        <button type="submit">Entra con Twitch</button>
      </form>
    </main>
  );
}
```

### 📡 Le chiamate alle API di Twitch
<br />
I canali seguiti si leggono da `GET /channels/followed` (è il motivo dello
scope `user:read:follows` di prima), i dettagli dei canali da `GET /users` e
le dirette in corso da `GET /streams/followed`. Le API di Twitch sono
paginate, quindi ci scriviamo un piccolo helper che gira le pagine fino in
fondo:

```typescript
// lib/twitch.ts
const TWITCH_API = 'https://api.twitch.tv/helix';

async function twitchGetAll(path: string, accessToken: string) {
  const items: any[] = [];
  let cursor: string | undefined;

  do {
    const url = `${TWITCH_API}${path}${cursor ? `&after=${cursor}` : ''}`;
    const response = await fetch(url, {
      headers: {
        'Client-Id': process.env.AUTH_TWITCH_ID!,
        Authorization: `Bearer ${accessToken}`,
      },
    });

    if (!response.ok) {
      throw new Error(`Twitch ha risposto ${response.status}`);
    }

    const data = await response.json();
    items.push(...data.data);
    cursor = data.pagination?.cursor;
  } while (cursor);

  return items;
}

// i canali seguiti dall'utente
export const getFollowedChannels = (userId: string, token: string) =>
  twitchGetAll(`/channels/followed?user_id=${userId}&first=100`, token);

// i dettagli dei canali (avatar, descrizione)
export const getUsers = (ids: string[], token: string) =>
  twitchGetAll(`/users?id=${ids.join('&id=')}`, token);

// chi è in live adesso, tra i canali seguiti
export const getFollowedStreams = (userId: string, token: string) =>
  twitchGetAll(`/streams/followed?user_id=${userId}&first=100`, token);
```

### 🏠 La homepage
<br />
La pagina principale è un server component: legge la sessione con `auth()`,
chiama le tre API e incrocia i risultati. Tutto sul server, il token non
tocca mai il browser.

```tsx
// app/page.tsx
import { auth } from '@/auth';
import { redirect } from 'next/navigation';
import {
  getFollowedChannels,
  getFollowedStreams,
  getUsers,
} from '@/lib/twitch';

export default async function Home() {
  const session = await auth();
  if (!session) redirect('/login');

  const { accessToken, userId } = session;

  const follows = await getFollowedChannels(userId, accessToken);
  const details = await getUsers(
    follows.map((f) => f.broadcaster_id),
    accessToken
  );
  const streams = await getFollowedStreams(userId, accessToken);

  const channels = details
    .sort((a, b) => a.display_name.localeCompare(b.display_name))
    .map((channel) => ({
      ...channel,
      stream: streams.find((s) => s.user_id === channel.id),
    }));

  return (
    <main className="channels">
      {channels.map((channel) => (
        <article key={channel.id} className="channel">
          <img src={channel.profile_image_url} alt={channel.display_name} />
          <h2>{channel.display_name}</h2>
          {channel.stream ? (
            <p className="live">🔴 LIVE · {channel.stream.title}</p>
          ) : (
            <p className="offline">offline</p>
          )}
        </article>
      ))}
    </main>
  );
}
```

Il flusso completo: sessione → canali seguiti → dettagli (ordinati per nome)
→ live in corso → merge. Lo stile lo lascio a te: la struttura è tutta qui.

> Una nota sul token scaduto: il token di Twitch dura qualche ora, e quando
> scade le API rispondono `401`. La gestione minima è intercettare l'errore
> e rimandare l'utente al login (`signOut` seguito da redirect); quella seria
> usa il **refresh token** che Twitch fornisce, rinnovando l'access token nel
> callback `jwt` quando sta per scadere. Per un progetto dimostrativo la
> prima basta; sappi che la seconda esiste, prima di andare in produzione.

### ✅ Conclusione
<br />
Ricapitolando: un'app registrata sulla console Twitch, Auth.js che gestisce
tutto il ballo OAuth con un provider e due callback, il token custodito lato
server e tre chiamate API incrociate per costruire la pagina. Il bello di
questo flusso è che è **riutilizzabile pari pari**: cambia il provider
(Google, GitHub, Discord...), cambiano gli scope e gli endpoint, ma lo
scheletro resta identico. Imparalo una volta con Twitch, e ogni "Accedi con"
che incontrerai sarà una variazione sul tema.
