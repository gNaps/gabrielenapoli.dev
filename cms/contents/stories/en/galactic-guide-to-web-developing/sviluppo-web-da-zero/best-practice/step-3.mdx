## 🧭 Where to go now
<br />
A truth courses rarely tell: from here, **there is no single path**. There are directions, chosen by what sparked your interest. Some fertile ones:
<br />
- **A frontend framework**: if those chapters were fun, a natural step. My admittedly interested but sincere advice: this site has a **complete Angular guide**, ten chapters by the same author, from zero to a real app.
- **TypeScript**: JavaScript with types, a compiler catching errors before users. Widely used professionally, and you are now ready.
- **Automated tests**: code checking code. A subject separating programming from engineering; the sooner you meet it, the better.
- **Security**: we planted seeds (never trust the client, injection, XSS, hashing). Interested? Look for the **OWASP Top 10**, the official list of major web security risks, explained case by case.
- **DevOps and deployment**: the Watch's register runs locally; taking it online (hosting, domains, CI/CD, chapter 10's cloud) is a whole field, easier to start than it seems.
<br />
One criterion: **follow curiosity rather than fashion**. The frameworks chapter applies here: popularity rankings change yearly; your foundations do not.
<br />
## 📚 Sources to trust
<br />
The internet overflows with developer content, ranging from excellent to harmful. Safe ports:
<br />
- **MDN Web Docs**: the reference for HTML, CSS and JavaScript. For web questions, start there.
- **Official documentation**: underrated by beginners. Modern docs (Node, Fastify, frameworks) are well written: learn to read them before tutorials.
- **roadmap.sh**: visual paths for frontend, backend and DevOps. Useful orientation, not gospel.
- **Communities**: Stack Overflow for specific questions, Italian and international Discord and Reddit communities for everything else. Programming is a team sport disguised as solitary work.
<br />
A word about **AI**, keeping chapter 3's promise: use it without guilt to explain errors, explore alternatives and get unstuck. Keep the familiar rule: AI accelerates people who can judge its output. Studying foundations has never mattered more now that code can be generated.
<br />
## 🔨 The method: build rather than collect
<br />
The most important advice concerns *how* to study. **Tutorial hell** means chaining courses with a sense of learning, without building anything of your own. One way out:

> For everything you study, **build something that did not exist**. Small, ugly, yours. The Watch's register is worth more than ten passively watched courses. You felt it: real learning happened when something failed and you struggled with it. Seek those moments. That is the craft.

Ideas for tomorrow: add castles (table, JOIN, routes: you have the tools), rebuild a minimal version of an everyday app, or take the Watch online. Put everything on GitHub: a profile full of projects is a résumé that matters.
